Verification and Troubleshooting

A deterministic bring-up sequence for checking firmware, serial transport, ROS 2 topic discovery, QoS compatibility, and the reference node.

Bring-up Flow

PX4 Checks

picocom -b 57600 /dev/ttyACM0
nsh> uxrce_dds_client status
nsh> uxrce_dds_client start -t serial -d /dev/ttyS1 -b 921600

If the command is unknown, rebuild with CONFIG_MODULES_UXRCE_DDS_CLIENT=y.

Agent Checks

boards/st/nucleo-h753zi/ros2_ref/scripts/run_agent_serial.sh /dev/ttyUSB0

Expected signs:

  • Serial initialization succeeds.
  • The agent creates a session for client key 0x00000001.
  • PX4 logs show DDS data writers and readers being created.

ROS 2 Topic Checks

source /opt/ros/humble/setup.bash
source ~/nucleo_px4_ros2_ws/install/setup.bash
ros2 topic list | grep /fmu

Examples that should appear:

/fmu/out/vehicle_status
/fmu/out/vehicle_odometry
/fmu/out/sensor_combined
/fmu/out/timesync_status

QoS-Compatible Echo

ros2 topic echo /fmu/out/vehicle_status \
  --qos-reliability best_effort \
  --qos-durability transient_local

Reference Node

boards/st/nucleo-h753zi/ros2_ref/scripts/run_reference_node.sh

Expected node output includes receive rates:

rx_hz vehicle_status=... vehicle_odometry=... sensor_combined=...

Confirm the ROS 2 to PX4 path from the PX4 shell:

nsh> listener onboard_computer_status

Common Failures

  • No agent session: swap TX/RX, connect grounds, verify 3.3 V logic, and check that no process owns /dev/ttyUSB0.
  • Agent session but no ROS topics: check ROS_DOMAIN_ID, namespace settings, and px4_msgs compatibility.
  • ros2 topic echo is silent: use best-effort and transient-local QoS for PX4 output topics.
  • HITL stops after DDS starts: confirm DDS is using /dev/ttyS1, not the CN13 USB MAVLink link.
