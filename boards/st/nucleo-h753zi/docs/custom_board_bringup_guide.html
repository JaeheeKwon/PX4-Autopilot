PX4 / NuttX Board Bring-Up

Custom Board Bring-Up Guide for STM32H7 PX4 Targets

A practical guide for creating and validating a custom PX4 board target. The examples use boards/st/nucleo-h753zi, but the workflow applies to other NuttX STM32H7 boards with the same platform layering.

Target family: STM32H7 / Cortex-M7 Host OS: NuttX Reference board: st_nucleo-h753zi Generated: 2026-06-23

Executive Summary

Core Principle

PX4 board bring-up is mostly a configuration and integration task. NuttX provides MCU-level lower-half drivers, PX4 provides reusable STM platform wrappers, and the custom board directory supplies the board-specific facts: clocks, pins, enabled peripherals, buses, timers, storage, LEDs, and startup defaults.

Bring-Up Strategy

Do not start by enabling every feature. Bring up the board in layers: bootloader, console, USB, HRT, parameter storage, buses, sensors, outputs, then application modules. Verify each layer before moving to the next one.

Rule of thumb

If the code describes an STM32 peripheral mechanism, it usually belongs to NuttX or the PX4 STM platform. If the code describes your board's concrete wiring or policy, it belongs under boards/<vendor>/<board>.

Layer Split

The most important bring-up skill is knowing which layer owns each decision. A wrong assumption here leads to duplicated drivers, board-specific hacks in platform code, or PX4 drivers that depend directly on GPIO pins.

Layer Provides You Usually Change You Usually Do Not Change
NuttX STM32H7 arch layer MCU-level drivers such as stm32_spi.c, stm32_i2c.c, stm32_pwm.c, stm32_gpio.c, stm32_dma.c. Enable options in board defconfig. The generic lower-half driver implementation, unless the MCU port is missing a real feature or has a bug.
PX4 STM platform layer Reusable PX4 wrappers for HRT, SPI chip-select glue, IO timers, board reset, versioning, work queues, uORB, params. Rarely. Prefer board-level configuration. Shared STM platform code for one custom board.
Board NuttX config Chip selection, clocks, peripheral enablement, alternate-function pins, linker scripts, memory layout. nuttx-config/nsh/defconfig, nuttx-config/include/board.h, scripts. Other board directories.
Board PX4 source PX4-facing board macros, LEDs, storage mount, buses, timers, board init, bootloader compatibility. src/board_config.h, src/init.c, src/i2c.cpp, src/spi.cpp, src/timer_config.cpp, src/led.c. PX4 sensor drivers unless adding a new sensor type.
PX4 application/driver modules Flight stack, sensors, MAVLink, actuator outputs, simulation modules. Board build selection through default.px4board and startup scripts. Direct board pin assumptions inside application modules.

File Bring-Up Role
default.px4board Selects PX4 modules, board architecture, param file path, serial configuration, and feature set for the application firmware.
bootloader.px4board Selects the bootloader build. STM32H7 PX4 bootloaders are NuttX-based.
nuttx-config/nsh/defconfig Enables MCU peripherals, NuttX features, serial devices, USB, filesystems, memory protection, and scheduler options.
nuttx-config/include/board.h Defines clock tree, PLLs, timer clocks, peripheral kernel clocks, UART/SPI/I2C alternate-function pins, and board LED indexes.
src/board_config.h Defines PX4-facing board macros: HRT timer, LEDs, GPIO init list, PWM output channel count, DMA pool size, and board common declarations.
src/init.c Owns board initialization: calls px4_platform_init(), initializes DMA pool, LEDs, storage, hardfault handling, and px4_platform_configure().
src/i2c.cpp Exports px4_i2c_buses, the PX4 bus list consumed by I2C/SPI driver framework.
src/spi.cpp Exports px4_spi_buses, including SPI bus numbers, chip selects, DRDY pins, and external/internal bus classification.
src/timer_config.cpp Maps STM32 timers/channels/pins to PX4 PWM input/output/capture infrastructure.
init/rc.board_early Sets early startup policy before normal parameter/storage flows complete.
init/rc.board_defaults Sets board default parameters such as HITL mode, sensor presence, serial defaults, and board-specific circuit breakers.

Finding Available MCU-Level Drivers

For STM32H7 targets, MCU-level drivers live in the NuttX STM32H7 arch layer. These are below PX4 drivers and below PX4's STM platform wrappers. 

platforms/nuttx/NuttX/nuttx/arch/arm/src/stm32h7/

Bring-Up Phases

Bring up one layer at a time. A board that boots to console and preserves parameters is a better foundation than a board that starts many drivers but cannot be diagnosed.

Phase 0: Collect Hardware Facts

Item Decisions To Record
MCU Exact part number, flash size, SRAM regions, cache behavior, package, boot pins, debug interface.
Clock tree HSE/LSE sources, PLL plan, SYSCLK, HCLK, PCLKs, USB 48 MHz source, timer clocks.
Console and USB Primary debug UART, USB device pins, VBUS sense, expected console device names.
Storage SD card, FRAM, EEPROM, internal flash filesystem, parameter file path, hardfault log path.
Buses I2C/SPI/CAN/UART bus numbers, internal vs external classification, power rails, chip selects, DRDY pins.
Outputs PWM timers/channels/pins, DShot support, safety switch, IO co-processor, actuator rail power.
Inputs RC input, PPM/SBUS/CRSF pins, capture timers, button inputs, safety inputs.
LEDs and power control LED polarity, power-enable GPIOs, sensor reset GPIOs, peripheral rail behavior.

Phase 1: Create The Board Skeleton

  1. Choose the closest existing board with the same MCU family and similar memory layout.
  2. Create boards/<vendor>/<board>.
  3. Add default.px4board, bootloader.px4board if needed, firmware.prototype, nuttx-config, src, and init.
  4. Keep the initial feature set small: console, USB, HRT, params, LEDs, and debug commands.
# Example target names for this board.
make st_nucleo-h753zi_default
make st_nucleo-h753zi_bootloader

Phase 2: Configure NuttX

Use nuttx-config/nsh/defconfig for the application image and nuttx-config/bootloader/defconfig for the bootloader image. 

# Edit with menuconfig when available.
make st_nucleo-h753zi_default menuconfig

# Review enabled MCU features.
rg -n "CONFIG_STM32H7|CONFIG_I2C|CONFIG_SPI|CONFIG_SERIAL|CONFIG_USB" \
  boards/st/nucleo-h753zi/nuttx-config/nsh/defconfig

Common NuttX config mistake

Defining pins in board.h does not enable a peripheral. The matching CONFIG_STM32H7_* option must also be enabled in defconfig. Likewise, enabling a peripheral in defconfig is not enough if the board pins and PX4 bus arrays are missing.

Phase 3: Define Clocks And Pins

Put NuttX clock and pin definitions in nuttx-config/include/board.h. For Nucleo-H753ZI, this includes the 8 MHz HSE, PLL1 at 400 MHz SYSCLK, peripheral kernel clocks, timer clocks, UART pins, SPI3 pins, and I2C1 pins. 

# Examples from the reference board.
#define STM32_BOARD_XTAL        8000000ul
#define STM32_BOARD_USEHSE

#define GPIO_USART3_RX  GPIO_USART3_RX_3
#define GPIO_USART3_TX  GPIO_USART3_TX_3

#define GPIO_SPI3_MISO  GPIO_SPI3_MISO_1
#define GPIO_SPI3_MOSI  GPIO_SPI3_MOSI_2
#define GPIO_SPI3_SCK   GPIO_SPI3_SCK_1

#define GPIO_I2C1_SCL   GPIO_I2C1_SCL_2
#define GPIO_I2C1_SDA   GPIO_I2C1_SDA_2

Phase 4: Define PX4 Board Facts

Put PX4-facing board macros in src/board_config.h. This file is where the PX4 platform learns board-level policy and resources. 

#define HRT_TIMER           5
#define HRT_TIMER_CHANNEL   1

#define BOARD_DMA_ALLOC_POOL_SIZE  5120
#define DIRECT_PWM_OUTPUT_CHANNELS  0

#define PX4_GPIO_INIT_LIST { \
    GPIO_OTGFS_VBUS,       \
}

Phase 5: Implement Board Initialization

src/init.c is the central bring-up file. It should configure board GPIOs, call the PX4 platform initialization, initialize board-only services, mount storage, and call px4_platform_configure(). 

__EXPORT int board_app_initialize(uintptr_t arg)
{
    px4_platform_init();

    board_dma_alloc_init();
    drv_led_start();
    mount_parameter_storage();

    px4_platform_configure();
    return OK;
}

Phase 6: Expose Buses And Timers

PX4 drivers discover board buses through board-provided arrays. The Nucleo reference board currently exposes SPI3 but no devices, and no I2C buses in the PX4 bus array. 

// src/i2c.cpp
constexpr px4_i2c_bus_t px4_i2c_buses[I2C_BUS_MAX_BUS_ITEMS] = {};

// src/spi.cpp
constexpr px4_spi_bus_t px4_spi_buses[SPI_BUS_MAX_BUS_ITEMS] = {
    initSPIBus(SPI::Bus::SPI3, {}),
};

// src/timer_config.cpp
constexpr io_timers_t io_timers[MAX_IO_TIMERS] = {};
constexpr timer_io_channels_t timer_io_channels[MAX_TIMER_IO_CHANNELS] = {};

When adding real sensors or outputs, these files change from empty/minimal arrays into the board's hardware manifest.

Phase 7: Add PX4 Modules And Startup Policy

Enable modules in default.px4board. Start board-specific hardware from init/rc.board_defaults, init/rc.board_early, or a sensor startup script depending on the feature. 

# default.px4board examples
CONFIG_MODULES_SENSORS=y
CONFIG_MODULES_MAVLINK=y
CONFIG_SYSTEMCMDS_DMESG=y
CONFIG_SYSTEMCMDS_UORB=y
CONFIG_SYSTEMCMDS_TOPIC_LISTENER=y

Peripheral Bring-Up Recipes

Console And USB

Step Files Validation
Enable UART/USART in NuttX. nuttx-config/nsh/defconfig Serial device appears as expected, for example /dev/ttyS0.
Map TX/RX pins. nuttx-config/include/board.h NSH prompt appears on the expected connector.
Enable USB device and VBUS sense. defconfig, board_config.h, usb.c Board enumerates as /dev/ttyACM0 or equivalent.

I2C

  1. Enable CONFIG_I2C and CONFIG_STM32H7_I2Cx in defconfig.
  2. Define GPIO_I2Cx_SCL and GPIO_I2Cx_SDA in board.h.
  3. Add the bus to src/i2c.cpp using initI2CBusInternal() or initI2CBusExternal().
  4. Enable and start the PX4 driver that probes the device.
constexpr px4_i2c_bus_t px4_i2c_buses[I2C_BUS_MAX_BUS_ITEMS] = {
    initI2CBusExternal(1),
};

SPI

  1. Enable CONFIG_SPI and CONFIG_STM32H7_SPIx in defconfig.
  2. Define GPIO_SPIx_SCK, GPIO_SPIx_MISO, and GPIO_SPIx_MOSI in board.h.
  3. Add devices and chip-select pins to src/spi.cpp.
  4. Add DRDY pins for interrupt-driven sensors when available.
  5. Enable the corresponding PX4 sensor driver.
constexpr px4_spi_bus_t px4_spi_buses[SPI_BUS_MAX_BUS_ITEMS] = {
    initSPIBus(SPI::Bus::SPI3, {
        initSPIDevice(DRV_IMU_DEVTYPE_BMI270, SPI::CS{GPIO::PortA, GPIO::Pin4},
                      SPI::DRDY{GPIO::PortB, GPIO::Pin0}),
    }),
};

SPI detail

SPI SCK/MISO/MOSI pins are NuttX alternate-function pins in board.h. Chip select and DRDY GPIOs are usually board-level PX4 device facts in src/spi.cpp. The shared PX4 STM SPI layer consumes px4_spi_buses and implements the select/status callbacks.

PWM / DShot / Timer IO

  1. Choose timers that do not conflict with HRT, capture inputs, or other board functions.
  2. Enable the needed timer/PWM Kconfig options in defconfig.
  3. Set DIRECT_PWM_OUTPUT_CHANNELS in board_config.h.
  4. Populate io_timers and timer_io_channels in timer_config.cpp.
  5. Enable CONFIG_DRIVERS_PWM_OUT or the relevant output driver in default.px4board.
// Conceptual example only. Choose timer/pins from your schematic and board.h.
constexpr io_timers_t io_timers[MAX_IO_TIMERS] = {
    initIOTimer(Timer::Timer1),
};

constexpr timer_io_channels_t timer_io_channels[MAX_TIMER_IO_CHANNELS] = {
    initIOTimerChannel(io_timers, {Timer::Timer1, Timer::Channel1}, {GPIO::PortE, GPIO::Pin9}),
};

Parameter Storage

Decide early where parameters live. The Nucleo reference board has no SD card, FRAM, or EEPROM, so it mounts a LittleFS partition in internal flash and sets CONFIG_BOARD_PARAM_FILE="/fs/flash/params". 

# default.px4board
CONFIG_BOARD_PARAM_FILE="/fs/flash/params"
CONFIG_BOARD_NO_SDCARD=y

If you use internal flash, check linker script regions carefully so the application, bootloader, and parameter filesystem do not overlap.

Verification Flow

Build Checks

# Application build.
make st_nucleo-h753zi_default

# Bootloader build.
make st_nucleo-h753zi_bootloader

# Optional menuconfig if changing NuttX options.
make st_nucleo-h753zi_default menuconfig

First-Boot Console Checks

Keep these commands enabled in early board builds: dmesg, ver, top, uorb, listener or topic_listener, work_queue, perf, param, and storage-specific tools such as mtd. 

# Basic identity and boot log.
ver all
dmesg

# Scheduler and PX4 runtime.
top
work_queue status

# uORB and modules.
uorb top
listener sensor_combined

# Parameters and storage.
param status
param show SYS_AUTOSTART

# Board manifest/config if enabled.
mft status

Layered Definition Of Done

Layer Done When
Bootloader Bootloader builds, flashes at the expected address, enters update mode, and can load the application image.
Application boot Board reaches NSH/PX4 startup repeatedly with no hard fault and correct clock speed.
Console Debug console is available from reset and does not conflict with MAVLink or RC ports.
USB USB enumerates reliably and VBUS detection matches the hardware connector.
HRT Timers work, scheduled work queues run, and no PWM/capture configuration uses the HRT timer accidentally.
Parameters Parameters survive reboot and the storage path does not corrupt application flash.
I2C/SPI Bus initializes, devices probe, communication errors remain bounded, and chip-select/DRDY behavior is correct.
Sensors Driver publishes the expected uORB topics with valid timestamps, device IDs, and update rates.
Outputs PWM/DShot outputs map to the expected pins, honor arming/disarmed/failsafe states, and do not conflict with timers.
Startup defaults Board boots into the intended mode without manual parameter edits.

Common Pitfalls

Symptom Likely Cause Where To Look
Peripheral pins defined but device never appears. Peripheral not enabled in defconfig, or bus not exposed in i2c.cpp/spi.cpp. nuttx-config/nsh/defconfig, board.h, board bus files.
SPI driver probes wrong device or no device. Wrong chip select, wrong device ID, missing power rail, wrong internal/external bus classification. src/spi.cpp, schematic, sensor driver start command.
No console or wrong serial device order. USART not enabled, pin alternate function wrong, serial reordering behavior not understood. defconfig, board.h, serial port mapping docs.
Bootloader flashes but app does not boot. Application load address, linker script, bootloader board ID, or flash region mismatch. hw_config.h, firmware.prototype, linker scripts.
Parameters reset every boot. Parameter file path invalid, filesystem not mounted before parameter load, no persistent storage. default.px4board, rc.board_early, init.c.
LEDs inverted. Board LED polarity differs from most PX4 boards. board_config.h, led.c, schematic.
PWM output does not appear. DIRECT_PWM_OUTPUT_CHANNELS is zero, timer array empty, Kconfig timer/PWM not enabled, or timer conflict. board_config.h, timer_config.cpp, defconfig.
Random DMA or bus corruption. Cacheable memory used for DMA, DMA pool too small, wrong DMA map, or alignment issue. board_dma_map.h, BOARD_DMA_ALLOC_POOL_SIZE, NuttX DMA config.
HITL starts but real sensors are silent. HITL defaults disable real sensors or GPS; physical drivers are not started. rc.board_defaults, SYS_HITL, sensor startup scripts.

Bring-Up Checklist

Status Item Evidence
Required Exact MCU and clock plan documented. board.h PLL and clock macros match schematic and measured behavior.
Required Bootloader and app memory map are consistent. Bootloader address, app load address, linker scripts, and firmware.prototype match.
Required Debug console available from reset. NSH prompt visible on documented connector.
Required PX4 platform initializes cleanly. ver all, dmesg, top, work_queue status work.
Required Persistent parameter storage works. Set a parameter, reboot, and verify it remains set.
Required Board buses are explicitly described. i2c.cpp, spi.cpp, and timer_config.cpp match schematic.
Required Board startup defaults match intended mode. HITL, real sensor, or actuator output behavior occurs without manual console edits.
Required for real sensors Each hardware sensor has a driver, bus, power rail, and startup command. Expected uORB topic updates at expected rate with stable device ID.
Required for actuators Output mapping, arming state, disarmed values, and failsafe values verified. Scope/logic analyzer confirms expected pin behavior.
Recommended Debug commands remain enabled until board is stable. dmesg, perf, uorb, listener, param, top available.
