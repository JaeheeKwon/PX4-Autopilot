Automatic Flight with Stored Waypoints on Nucleo-H753ZI¶

This page explains how automatic waypoint flight is implemented and tested on the ST Nucleo-H753ZI PX4 target. The board has no onboard flight sensors in the default configuration, so this workflow is for Hardware-In-the-Loop simulation (HITL): the simulator provides sensor data, PX4 runs the real mission and control stack on the STM32H753, and pwm_out_sim sends actuator commands back to the simulator.

For the base HITL setup, see Nucleo-H753ZI HITL Configuration and Parameters. The markdown source for this page is auto_flight_waypoint_mission.md.

Concept¶

Automatic waypoint flight should use PX4 Mission mode rather than custom motor, attitude, or position-control code. The mission layer owns the route and mode progression; the existing controllers own vehicle stabilization.

The mission data is stored as mission_item_s entries. Navigation commands are defined in src/modules/navigator/navigation.h, including:

CommandUse
NAV_CMD_TAKEOFFClimb from the launch point to the mission takeoff altitude.
NAV_CMD_WAYPOINTFly to a latitude, longitude, and altitude.
NAV_CMD_LOITER_TIME_LIMITHold around a point for a fixed time.
NAV_CMD_LANDLand at the final mission point.
NAV_CMD_RETURN_TO_LAUNCHReturn to the home position.

Mission Storage on This Board¶

PX4 stores missions in dataman using these key areas:

Dataman keyPurpose
DM_KEY_WAYPOINTS_OFFBOARD_0Active or previous uploaded mission item set.
DM_KEY_WAYPOINTS_OFFBOARD_1Alternate mission item set used during upload/update.
DM_KEY_MISSION_STATEMission metadata such as current sequence and selected storage key.

This target sets CONFIG_DATAMAN_PERSISTENT_STORAGE to disabled, so dataman falls back to RAM. That means:

  • A mission uploaded after boot can be flown normally.
  • The uploaded mission is lost on reboot.
  • "Pre-stored" means stored for the current boot session unless persistent storage is added.

For a mission that must survive reboot, use one of these approaches:

ApproachWhen to use
Enable persistent dataman storageUse this when the board has a mounted filesystem or a LittleFS-backed storage area available for mission files.
Upload after every bootUse this for HITL validation from QGC, MAVSDK, or a companion script.
Add a mission preload moduleUse this when a fixed built-in route must be written into dataman at boot before Mission mode is started.

Do not bypass navigator for stored waypoint flight. A preload path should only write valid mission items and mission metadata, then let normal Mission mode execute the route.

Mission Contents¶

A minimal multicopter mission for this board should contain:

SequenceMission item
0Takeoff to a safe relative altitude.
1First waypoint near the simulator home position.
2..NAdditional waypoints.
N+1Land, or return-to-launch.

Keep the first mission near the simulator start location. PX4 performs mission feasibility checks before execution, and a route too far from home may be rejected.

Typical waypoint fields:

FieldMeaning
lat, lonWGS84 waypoint position in degrees.
altitudeMission altitude in meters.
altitude_is_relativeUse relative altitude when the route is planned above the home position.
acceptance_radiusRadius where the waypoint counts as reached.
yawDesired yaw in radians, or NaN to let PX4 choose yaw behavior.
autocontinueContinue to the next item after this one is reached.

Run Workflow¶

  1. Flash and boot the Nucleo-H753ZI PX4 firmware.
  2. Start the HITL simulator on CN13 User USB.
  3. Open QGroundControl or a MAVSDK mission uploader.
  4. Create a mission with takeoff, nearby waypoints, and land or RTL.
  5. Upload the mission to the vehicle.
  6. Wait for valid local and global position estimates.
  7. Arm the vehicle.
  8. Start Mission mode.

From the MAVLink console or NSH, Mission mode can be requested with:

commander mode auto:mission

If the mission is valid and the vehicle is allowed to arm, QGroundControl can also start the mission using its normal mission start controls.

Runtime Checks¶

Use these commands while the simulator is running:

dataman status
listener mission
listener mission_result
listener position_setpoint_triplet
listener vehicle_local_position
listener vehicle_global_position

Expected behavior:

  • listener mission shows a nonzero count.
  • listener mission_result shows valid: true and the current mission sequence.
  • listener position_setpoint_triplet shows the current and next waypoint setpoints while Mission mode is active.
  • listener vehicle_local_position and listener vehicle_global_position update from HITL sensor data.
  • The simulator receives HIL_ACTUATOR_CONTROLS from pwm_out_sim.

Implementation Guidance¶

If a built-in route is required, keep the implementation narrow:

  1. Define the route as normal mission items.
  2. Write those items to DM_KEY_WAYPOINTS_OFFBOARD_0 or _1.
  3. Write matching mission_s metadata to DM_KEY_MISSION_STATE.
  4. Publish or trigger a mission update so navigator reloads the mission.
  5. Start Mission mode through commander.

The preload code should not publish actuator commands and should not directly control attitude, rates, or motors. Those responsibilities belong to the PX4 controller stack.
