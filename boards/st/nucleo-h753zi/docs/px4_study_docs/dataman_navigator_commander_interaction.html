Dataman, Navigator, and Commander Interaction

How persistent mission storage, autonomous navigation, and vehicle mode management cooperate in PX4.

Short Answer

Dataman
Stores mission, geofence, safe-point, and mission-state records. It is a persistence service, not a navigation decision maker.
Navigator
Reads mission/geofence records through DatamanClient, selects autonomous behavior from commander state, and publishes setpoints plus mission/geofence status.
Commander
Owns arming, mode selection, health checks, and failsafe decisions. It publishes vehicle_status and reacts to navigator feedback.

The coupling is mostly asynchronous through uORB topics. Dataman is accessed through request/response messages. Navigator and MAVLink mission handling use those services. Commander does not normally read mission items directly from dataman; it consumes navigator's mission and geofence results and decides whether automatic modes are allowed or should be changed.

Mission Upload And Storage

Mission upload is not performed by navigator or commander. MAVLink mission handling writes mission items into dataman, then updates the active mission state. PX4 uses two offboard waypoint banks, DM_KEY_WAYPOINTS_OFFBOARD_0 and DM_KEY_WAYPOINTS_OFFBOARD_1, so a new mission can be received into the inactive bank and then atomically selected by updating DM_KEY_MISSION_STATE.

Runtime Control Loop

Commander controls the selected high-level mode by publishing vehicle_status.nav_state. Navigator reads that state and chooses an internal NavigatorMode. If the state is NAVIGATION_STATE_AUTO_MISSION, navigator activates mission mode, loads the relevant dataman-backed mission items, and generates setpoints. If commander switches to RTL, takeoff, land, or loiter, navigator changes its active mode accordingly.

Navigator Feedback To Commander

Navigator is the module that knows whether a mission is feasible, where it is in the mission, and whether geofence limits are violated. Commander is the module that decides how those facts affect the vehicle state.

Navigator outputWhat it meansCommander use
mission_result.valid Mission feasibility checker passed for the current mission ID, geofence ID, and home-position update count. Commander treats auto mission as available only when the result is current and valid.
mission_result.finished Mission, takeoff, or landing mode has completed its current autonomous task. Commander changes from auto takeoff or auto mission into auto loiter when appropriate.
mission_result.seq_current / seq_reached Navigator's current and reached mission item indexes. Used for operator visibility, mission progress, and mission state reasoning.
geofence_result Navigator's geofence checks against max distance, max altitude, and custom fence geometry. Commander health checks set failsafe_flags.geofence_breached; failsafe then applies the configured GF_ACTION.
rtl_status Navigator's RTL planning state and safe-point status. Commander uses RTL/failsafe context when evaluating mode outcomes and remaining flight behavior.

Geofence Path

Geofence configuration can be stored in dataman, but the actual breach test is performed by navigator. Commander does not run the polygon/circle checks itself. Commander receives geofence_result, reports the health check condition, and routes the final action through failsafe logic.

Home Position Dependency

Home position is a key shared fact. Commander normally owns setting and publishing home_position from estimator/global/local position validity and arming state. Navigator uses home position for mission feasibility, RTL planning, takeoff/landing reference altitudes, and geofence distance/altitude checks. When the home-position update count changes, navigator revalidates mission feasibility because relative altitudes and home-based constraints may have changed.

Failure And Edge Cases

CaseWhere detectedResulting behavior
Dataman read fails for a mission item. Navigator mission cache/client or mission feasibility checker. Navigator marks the mission invalid or failed through mission_result; commander does not treat the mission as a valid auto mission.
Mission upload changes active mission ID. MAVLink mission manager writes DM_KEY_MISSION_STATE and publishes mission. Navigator reloads/revalidates; commander sees the new mission_result.mission_id.
Geofence breach. Navigator geofence check. Navigator publishes geofence_result; commander sets failsafe flags and applies GF_ACTION.
Mission finishes while armed in auto mission. Navigator mission mode sets mission_result.finished. Commander moves the user mode intention to auto loiter if no other mode change is pending.
Vehicle is disarmed. Commander publishes disarmed state in vehicle_status. Navigator does not execute its autonomous mode state machine while disarmed.
Key design point: dataman is durable storage, navigator is autonomous navigation logic, and commander is authority over vehicle mode and safety. The modules stay decoupled by passing mission metadata, status, and commands through uORB instead of direct cross-module ownership.
