Summary

Commander uses two layers before arming. First, Commander::arm() handles direct transition gates: already armed, calibration in progress, RC re-arm grace, manual throttle position, and whether checks should run. Second, HealthAndArmingChecks::update() runs the check framework and computes mode-specific can_arm and can_run bitmasks.

The final normal decision is:

_health_and_arming_checks.update(false, true);
if (!_health_and_arming_checks.canArm(_vehicle_status.nav_state)) {
    return TRANSITION_DENIED;
}

canArm(nav_state) is mode-specific. Some failures clear all modes, some clear only modes that need the failed resource, and warning-only checks use NavModes::None so they report without blocking arming.

Periodic Preflight Flow

The main loop runs health-and-arming checks at 10 Hz, or immediately when vehicle status or failsafe-relevant state changes. The result updates vehicle_status.pre_flight_checks_pass and actuator_armed.ready_to_arm.

    start["Commander loop tick"] --> updates["Update inputs"]
    updates --> due{"Run checks now"}
    due -->|no| commands["Handle commands"]
    due -->|yes| run_checks["Run health checks"]
    run_checks --> can_arm["Evaluate current mode"]
    can_arm --> store["Store preflight result"]
    store --> ready["Publish ready to arm"]

Logical State Machine

The firmware arming enum is essentially disarmed or armed; prearmed and ready_to_arm are separate actuator_armed flags. This is a logical view.

stateDiagram-v2
    [*] --> Disarmed
    Disarmed --> Prearmed: prearm allowed
    Prearmed --> Disarmed: safety on
    Disarmed --> ReadyToArm: checks pass
    ReadyToArm --> Blocked: check fails
    Blocked --> ReadyToArm: failure clears
    ReadyToArm --> Armed: arm accepted
    Blocked --> Denied: arm denied
    Denied --> Blocked: stay disarmed
    Blocked --> Armed: checks skipped
    Armed --> ArmedDegraded: degraded condition
    ArmedDegraded --> Armed: condition clears
    Armed --> Disarmed: disarm event

Decision Model

  1. Report::reset() starts a fresh result.
  2. Report::prepare(vehicle_type) fills failsafe_flags.mode_req_* masks.
  3. Every check class runs checkAndReport().
  4. healthFailure() and armingCheckFailure() set component flags and clear relevant can_arm bits.
  5. clearCanRunBits() prevents mode switching while armed.
  6. finalize() marks the result valid; report() emits rate-limited events.
  7. health_report is published when reporting happens; failsafe_flags is published every 500 ms or on changes.
