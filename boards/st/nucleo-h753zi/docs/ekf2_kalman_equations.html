1. Filter Structure

EKF2 is an error-state EKF. The vehicle attitude is stored as a four-element nominal quaternion, but the covariance uses a three-element small-angle attitude error. This is why the published nominal state has 25 scalars while the Kalman matrices are \(24 \times 24\).

\[ x = \begin{bmatrix} q_{0:3} & v_N & v_E & v_D & p_N & p_E & p_D & b_{g,x:y:z} & b_{a,x:y:z} & m_{I,N:E:D} & m_{B,x:y:z} & w_N & w_E & t \end{bmatrix}^T \] \[ \delta x = \begin{bmatrix} \delta\theta_{0:2} & \delta v_{N:E:D} & \delta p_{N:E:D} & \delta b_{g,x:y:z} & \delta b_{a,x:y:z} & \delta m_{I,N:E:D} & \delta m_{B,x:y:z} & \delta w_{N:E} & \delta t \end{bmatrix}^T \]

The generated state header defines StateSample with quaternion, velocity, position, gyro bias, accelerometer bias, earth magnetic field, body magnetic bias, wind velocity, and terrain. The tangent-space index table then maps these blocks into the 24-element covariance state.

State block Nominal storage Covariance index Meaning
quat_nominal 0..3, 4 scalars 0..2, 3 DOF Quaternion rotating body frame to NED navigation frame.
vel 4..6 3..5 Velocity in NED, meters per second.
pos 7..9 6..8 Position error in NED. In this implementation horizontal position is accumulated in _gpos; pos(2) stores down position from altitude.
gyro_bias 10..12 9..11 Gyroscope bias, radians per second.

The quaternion/Euler conversion equations and the body-frame to NED rotation matrix are derived in the separate document Quaternion and NED Conversion Derivations. EKF2 uses those rotations when converting IMU body-frame delta velocity into the NED navigation frame.

2. Nominal State Prediction

EKF2 predicts the delayed-horizon nominal state from downsampled IMU delta angles and delta velocities. In the C++ implementation, gyro and accelerometer biases are applied to the integrated IMU increments before updating attitude and velocity.

Bias-corrected IMU increments

\[ \Delta\theta_c = \Delta\theta_{imu} - b_g \Delta t_\theta - R(q_k)^T \omega_{ie}^{n} \Delta t_\theta \] \[ \Delta v_c = \Delta v_{imu} - b_a \Delta t_v \]

\(R(q)\) rotates body-frame vectors into the NED/navigation frame. The earth-rate correction appears in the handwritten state predictor; the symbolic covariance model is simpler and does not include every navigation correction term.

Attitude, velocity, and position

\[ q_{k+1} = \operatorname{normalize}\left(q_k \otimes \operatorname{Exp}(\Delta\theta_c)\right) \] \[ v_{k+1} = v_k + R(q_{k+1})\Delta v_c + \left(g^n - 2\omega_{ie}^{n}\times v_k - \omega_{en}^{n}\times v_k\right)\Delta t_v \] \[ p_{k+1} = p_k + \frac{1}{2}\left(v_k + v_{k+1}\right)\Delta t_v \]

In code, EKF2 performs the covariance prediction first and then calls the nominal predictState(). The nominal predictor uses exact axis-angle quaternion construction, current attitude to rotate delta velocity, gravity, Coriolis, transport-rate acceleration, and trapezoidal position integration.

Static process states

Biases, magnetic field states, wind, and terrain are nominally held constant during the prediction step. Their uncertainty grows through explicit process-noise additions in predictCovariance().

\[ b_{g,k+1}=b_{g,k},\quad b_{a,k+1}=b_{a,k},\quad m_{I,k+1}=m_{I,k},\quad m_{B,k+1}=m_{B,k},\quad w_{k+1}=w_k,\quad t_{k+1}=t_k \]

3. Error-State Covariance Prediction

The generated covariance model is derived directly in discrete time. It constructs a true state by perturbing the nominal state in tangent space, propagates both true and nominal states, computes the next error state, and differentiates it.

\[ q^t = \operatorname{Exp}(\delta\theta)\otimes q,\qquad y^t = y + \delta y \quad \text{for all non-attitude state blocks} \] \[ u^t = \begin{bmatrix} a_m - b_a^t - n_a\\ \omega_m - b_g^t - n_g \end{bmatrix} \] \[ A = \left.\frac{\partial f_{\delta}(\delta x,n)}{\partial \delta x}\right|_{\delta x=0,n=0}, \qquad G = \left.\frac{\partial f_{\delta}(\delta x,n)}{\partial n}\right|_{\delta x=0,n=0} \] \[ Q_u = \operatorname{diag} \left(\sigma_{a_x}^2,\sigma_{a_y}^2,\sigma_{a_z}^2, \sigma_g^2,\sigma_g^2,\sigma_g^2\right) \] \[ P_{k+1}^{-} = A P_k^{+} A^T + G Q_u G^T \]
The generated function has signature PredictCovariance(state: Matrix25_1, P: Matrix24_24, accel, accel_var, gyro, gyro_var, dt) and returns a Matrix24_24. The generated header reports 1810 scalar operations and 144 intermediate terms for this checkout.

Symmetry and additional process noise

The symbolic generator only emits the upper triangle and diagonal of \(P\). After calling sym::PredictCovariance(), EKF2 adds process noise to stationary process states, mirrors the upper triangle into the lower triangle, and constrains variances. 

P = sym::PredictCovariance(...);

// Additional diagonal process noise is added for gyro bias, accel bias,
// magnetic field, magnetic bias, wind, and terrain when those blocks exist.

for row in 0..State::size-1:
  for col in 0..row-1:
    P(row, col) = P(col, row)

4. Measurement Update Equations

EKF2 uses sequential fusion. A scalar observation is fused at a time, or a vector observation is broken into scalar updates. For nonlinear sensors, generated code computes the predicted measurement, Jacobian, and innovation variance.

Innovation and gain

\[ \hat z = h(x^-),\qquad r = \hat z - z \] \[ H = \left.\frac{\partial h(x\boxplus\delta x)}{\partial \delta x}\right|_{\delta x=0}, \qquad S = HPH^T + R \] \[ K = PH^T S^{-1} \]

The sign convention matters: most EKF2 innovations are predicted minus observed. The error-state correction applied to the nominal state is therefore \(\hat{\delta x}=-K r\).

State correction

\[ \hat{\delta\theta} = -K_{\theta}r,\qquad q^+ = \operatorname{Exp}(\hat{\delta\theta})\otimes q^- \] \[ y^+ = y^- - K_y r \quad \text{for velocity, biases, magnetic field, wind, and terrain} \] \[ p^+ = p^- - K_p r \]

The implementation applies the position correction to _gpos, clears _state.pos, and stores pos(2)=-altitude. This matches comments in the ranging-beacon fusion path: horizontal _state.pos(0:1) is always zero in the global-position EKF, and horizontal local position is projected from _gpos.

Joseph-stabilized covariance update

\[ P^+ = (I-KH)P^-(I-KH)^T + K R K^T \]

This is the mathematically clear form. EKF2 keeps the Joseph form but computes it without constructing \(I-KH\).

\[ P_{temp}=P^- - K(HP^-) \] \[ P^+ = P_{temp} - (P_{temp}H^T)K^T + K R K^T \]

For direct state observations, \(H\) is a one-hot selector. EKF2 computes \(K_i=P_{i,j}/S\), uses row j for the first covariance pass, then uses column j for the stabilized pass. For generated nonlinear observations, it computes PH = P * H in both passes.

5. Delayed Fusion Time Horizon

EKF2 uses two time horizons because IMU data is fast and nearly continuous, while aiding sensors such as GNSS, barometer, optical flow, range finder, and external vision are slower and often delayed. The EKF core fuses those slow measurements in the past, then the output predictor propagates the corrected estimate back to the current time.

Step-by-step flow

  1. Fast IMU data arrives. Every IMU sample updates the output predictor immediately, so PX4 has a continuously propagated current-time attitude, velocity, and position estimate.
  2. IMU data is downsampled for the EKF core. EKF2 accumulates delta angle and delta velocity, constrains the integration interval, and pushes downsampled IMU samples into the IMU ring buffer.
  3. The EKF fusion horizon is intentionally delayed. EKF2 sets _time_delayed_us from the oldest IMU sample in the buffer:
\[ t_{fusion}=t_{latest}-t_{delay} \]
  1. Slow sensors are buffered by timestamp. A GNSS, barometer, vision, range, or optical-flow sample is not fused as if it happened now. It waits in its observation buffer until the delayed EKF horizon reaches the sample time.
  2. The measurement is fused against the matching past state. A delayed sensor observation \(z(t_s)\) is fused with the EKF state at approximately the same time:
\[ z(t_s) \quad \text{is fused with} \quad x(t_{fusion}\approx t_s) \]
  1. The EKF predicts and fuses at the delayed horizon. Each EKF update predicts state and covariance with delayed IMU data, then runs the sensor fusion controllers at that delayed time.
  2. The output predictor applies the delayed correction. After the EKF state is corrected at the delayed horizon, the output predictor compares that corrected EKF state with its own buffered state at the same time and applies the correction to the current output history.
  3. PX4 publishes current-time outputs. The estimator fuses slow measurements in the past, but the published attitude, local position, global position, and odometry are propagated to the current IMU horizon for controllers and logging.

Why this is needed

If an old GNSS or vision measurement were fused directly into the current IMU-propagated state, the EKF would interpret timing error as real state error. That can create false position, velocity, or attitude corrections. The delayed horizon avoids that by aligning each slow measurement with the state it actually observed. 

Fast IMU now  -> output predictor -> current output
Slow sensors  -> observation buffers -> delayed EKF fusion
Delayed EKF correction -> output predictor -> corrected current output

Implementation map

The relevant EKF2 code paths are:

  • EstimatorInterface::setIMUData(): updates the output predictor, downsamples IMU, pushes IMU into the buffer, and updates _time_delayed_us.
  • EstimatorInterface::initialise_interface(): sizes IMU and observation buffers from EKF2_DELAY_MAX and EKF2_PREDICT_US.
  • Ekf::update(): predicts covariance/state with delayed IMU data and runs sensor fusion.
  • OutputPredictor::correctOutputStates(): applies delayed EKF corrections to the output predictor history.

6. Convergence and Sensor Covariance

What the coordinate conversions guarantee

Quaternion and NED conversion equations guarantee a valid coordinate rotation only when the quaternion is normalized. A unit quaternion produces an orthonormal rotation matrix:

\[ \|q\|=1 \quad \Longrightarrow \quad R(q)^T R(q)=I \] \[ v^n=R^n_b(q)v^b \]

This guarantees that a body-frame vector is rotated into NED without scaling or shearing. It does not, by itself, guarantee EKF convergence.

What EKF convergence depends on

EKF2 is a nonlinear estimator, so global convergence is not mathematically guaranteed. In practice it converges when the initial state is close enough, the process and observation models are valid, the relevant states are observable, noise values are realistic, and bad measurements are rejected or reset safely.

EKF2 improves practical convergence by normalizing quaternion states, using a Joseph-stabilized covariance update, gating innovations, constraining covariance growth, resetting states when needed, fusing measurements sequentially, and aligning delayed sensor data with the EKF fusion horizon.

How sensor covariance enters EKF2

The EKF measurement covariance is the observation variance \(R\). EKF2 combines it with the projected state covariance to form the innovation variance \(S\):

\[ R = \operatorname{cov}(z),\qquad S = HPH^T + R,\qquad K = PH^T S^{-1} \]

Larger \(R\) means the sensor is trusted less and the Kalman gain is smaller. Smaller \(R\) means the sensor is trusted more, but unrealistically small covariance can cause rejection, inconsistency, or unstable corrections.

Where to provide a sensor covariance

There is no single global "set covariance" call for every EKF2 aid source. Covariance enters through the specific sensor message fields or through EKF2 noise parameters:

Implementation pattern

Sensor-specific code computes an observation variance, passes it into updateAidSourceStatus(), and later fuses it through measurementUpdate() or fuseDirectStateMeasurement(). 

observation_variance = sensor_reported_variance_or_param_floor;
innovation_variance = H * P * H.T + observation_variance;
K = P * H / innovation_variance;
measurementUpdate(K, H, observation_variance, innovation);

8. Optimized Implementation Details

Generated covariance prediction

derivation.py constructs symbolic \(A\), \(G\), and \(P_{new}\), then zeroes lower-triangular terms before code generation. The C++ caller mirrors the upper triangle afterward.

Generated observation Jacobians

For nonlinear sensors, generated functions compute \(H\) in the 24-dimensional tangent space using a chain rule from quaternion storage to attitude error.

Sequential scalar fusion

Multi-axis measurements are fused one scalar at a time. This reduces matrix dimensions and lets EKF2 reject or constrain individual axes.

Joseph update without dense temporaries

EKF2 keeps the stabilized covariance formula but avoids forming \(I-KH\), using row and column products directly against the row-major matrix.

Gain inhibition and state limits

Before covariance and state correction, inhibited-state gains are cleared. After covariance correction, state variances are constrained to prevent numerical runaway.

Delayed and current horizons

The EKF itself runs at a delayed fusion horizon; the output predictor propagates corrected states to the current IMU horizon for publication and control.

10. Notes and Caveats

  • The full generated state in this checkout includes magnetometer, wind, and terrain blocks. Build-time configuration controls which fusions and process-noise blocks are active.
  • The symbolic covariance model uses a simplified discrete-time process model for tractable Jacobians. The handwritten nominal prediction includes additional navigation terms and more accurate integration.
  • Most EKF2 innovations use predicted minus measured sign convention, so the state correction is applied as state - K * innovation.
