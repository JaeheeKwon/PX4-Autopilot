USART6 Minicom Quick Test

Verify Nucleo-H753ZI USART6 transmit and receive independently of Micro XRCE-DDS using the PX4 usart6_hello command.

Board: MB1364 · PX4 device: /dev/ttyS1 · Host tool: minicom · Default: 921600 8-N-1

Fast path

  1. Build and flash the updated firmware.
  2. Wire PG14→adapter RX, PG9←adapter TX, and GND↔GND.
  3. Open CN1 NSH console, stop uxrce_dds_client.
  4. Open the adapter in minicom at 921600 8-N-1, no flow control.
  5. Run usart6_hello -t 30 from NSH.
  6. Observe hello lines, type characters, and confirm PX4 RX replies and a PASS result.
  7. Exit minicom and reboot PX4 to restore DDS.

1. What this test proves

ObservationProven path
Readable PX4 hello lines in minicomSTM32 USART6 TX → PG14/CN12-61 → adapter RX → host USB.
Typing in minicom produces PX4 RX 0x..Host USB → adapter TX → PG9/CN11-63 → STM32 USART6 RX.
NSH prints PASS and command exits 0At least one byte was received and both directions worked.
NSH warning and exit 2TX ran, but PX4 received no host byte; investigate RX direction.
Exclusive-port rule: USART6 is normally owned by uxrce_dds_client. Stop it before this test. The Micro XRCE-DDS Agent and minicom must never open the same host serial device simultaneously.

2. Wiring

Nucleo-H753ZI (3.3 V)                         USB-UART adapter

│ CN12-61  PG14 USART6_TX  ├────────────────►│ RX                    │
│ CN11-63  PG9  USART6_RX  │◄────────────────┤ TX                    │
│ CN12-63  GND             ├─────────────────┤ GND                   │
│                          │        X        │ VCC / 5V / 3V3 OUT   │
│ powered through CN1 USB  │     no wire     │ powered by host USB   │
└──────────────────────────┘                 └───────────┬───────────┘
                                                        │ USB
                                             /dev/serial/by-id/...
  • Use a 3.3 V TTL/CMOS adapter, not a true ±RS-232 adapter.
  • Leave VCC, RTS, CTS, DTR, and DSR disconnected.
  • No MB1364 solder-bridge change is required for USART6.
  • Keep SB12/SB19 ON; those belong to the separate USART3 ST-LINK console.
  • Do not use Arduino D0/D1. PG14 is also D2, but PG9 RX is on CN11-63.

See the signal-level connection diagram for full electrical and interface detail.

3. Why board customization is required

An STM32 UART does not appear merely because application code opens a device name. Four configuration layers must agree.

3.1 NuttX peripheral and device configuration

nuttx-config/nsh/defconfig enables the hardware driver and sets its initial properties:

CONFIG_STM32H7_USART3=y
CONFIG_STM32H7_USART6=y
CONFIG_STM32H7_SERIAL_DISABLE_REORDERING=y
CONFIG_USART3_SERIAL_CONSOLE=y
CONFIG_USART6_BAUD=921600
CONFIG_USART6_RXBUFSIZE=512
CONFIG_USART6_TXBUFSIZE=512

USART3 is the console and USART6 is the second enabled hardware USART. With serial reordering disabled, numeric peripheral ordering gives USART3 /dev/ttyS0 and USART6 /dev/ttyS1. Enabling another lower-numbered USART can change that assumption; recheck generated NuttX configuration and boot output after such a change.

3.2 NuttX board pin selection

nuttx-config/include/board.h selects the actual MCU alternate-function pins:

#define GPIO_USART6_RX  GPIO_USART6_RX_2   /* PG9,  CN11-63 */
#define GPIO_USART6_TX  GPIO_USART6_TX_2   /* PG14, CN12-61 / D2 */

For STM32H753, these pin-map macros expand to alternate function AF7. The RX definition enables a pull-up; TX is push-pull with pull-up. A different custom baseboard may expose different legal USART6 pins, requiring different GPIO_USART6_RX_n/TX_n selections.

3.3 PX4 logical serial mapping and command inclusion

default.px4board maps the NuttX device into PX4's serial configuration and includes this diagnostic:

CONFIG_BOARD_SERIAL_TEL1="/dev/ttyS1"
CONFIG_MODULES_UXRCE_DDS_CLIENT=y
CONFIG_SYSTEMCMDS_USART6_HELLO=y

The first line gives PX4 the TEL1-to-device relationship. The test command itself can open /dev/ttyS1 without TEL1, but DDS parameter-driven startup requires the logical mapping.

3.4 Runtime ownership

init/rc.board_defaults assigns TEL1 to DDS:

UXRCE_DDS_CFG = 101
SER_TEL1_BAUD = 921600

This does not enable the STM32 peripheral or choose pins; NuttX does that. It tells PX4 startup which already-created serial device the DDS client should own. Therefore the DDS client must be stopped temporarily for the raw minicom test.

3.5 Checklist when porting to another custom board

  1. Choose MCU pins with the correct USART alternate function and confirm header availability.
  2. Define the selected GPIO macros in the board header.
  3. Enable the USART and buffers in the NuttX defconfig.
  4. Confirm the resulting /dev/ttySx number; do not assume it.
  5. Map a PX4 logical port to that device in the board .px4board.
  6. Ensure only one runtime consumer owns the port.
  7. Match voltage, framing, baud, and flow control on both ends.

4. Build and flash

make st_nucleo-h753zi_default
make st_nucleo-h753zi_default upload

The build containing usart6_hello uses 1,348,928 / 1,441,792 bytes (93.56%), leaving 92,864 bytes.

After boot, confirm the command exists on the CN1 NSH console:

nsh> usart6_hello -h

If NSH says command not found, the new image was not built/flashed or CONFIG_SYSTEMCMDS_USART6_HELLO is absent.

5. Configure minicom on the host

5.1 Install and obtain serial permission

sudo apt update
sudo apt install -y minicom
sudo usermod -aG dialout "$USER"

Log out and in after changing groups. Identify the adapter:

ls -l /dev/serial/by-id/
udevadm info --query=all --name=/dev/ttyUSB0

5.2 Recommended saved minicom profile

minicom -s

Under Serial port setup, configure:

FieldValue
Serial device/dev/serial/by-id/<usb-uart-adapter>
Bps/Par/Bits921600 8N1
Hardware flow controlNo
Software flow controlNo
Local echoOff; PX4 will echo received bytes explicitly.

Save as usart6_px4, then run:

minicom usart6_px4

One-time command-line alternative:

minicom -o -8 -b 921600 \
  -D /dev/serial/by-id/<usb-uart-adapter>

Verify flow control is disabled with Ctrl-A, Z, O if the saved/default configuration is uncertain. Exit minicom with Ctrl-A, X.

6. Test procedure

6.1 Open the independent CN1 NSH console

Use a second terminal and the ST-LINK VCP at 57600. For example:

minicom -o -8 -b 57600 \
  -D /dev/serial/by-id/<stlink-vcp>

Press Enter until nsh> appears.

6.2 Stop DDS and release USART6

nsh> uxrce_dds_client status
nsh> uxrce_dds_client stop
nsh> uxrce_dds_client status

Also stop MicroXRCEAgent on the host. If minicom shows binary-looking data before the stop, that is XRCE framing, not a UART failure.

6.3 Open adapter minicom

minicom usart6_px4

The screen should be quiet after DDS is stopped.

6.4 Run the PX4 hello/echo test

On the CN1 NSH console:

nsh> usart6_hello -d /dev/ttyS1 -b 921600 -t 30 -i 1000

Expected adapter-minicom output:

PX4 USART6 HELLO
device=/dev/ttyS1 baud=921600 format=8N1 flow=none
Type characters in minicom; PX4 reports each received byte.
PX4 hello #0 uptime_us=...
PX4 hello #1 uptime_us=...

Type abc in the adapter minicom window. Expected replies:

PX4 RX 0x61 'a'
PX4 RX 0x62 'b'
PX4 RX 0x63 'c'

At timeout:

PX4 USART6 TEST PASS rx_bytes=3 tx_bytes=...

The CN1 console prints:

INFO  [usart6_hello] PASS: USART TX and RX worked (3 received bytes)
PASS: periodic hello is readable, typed bytes are reported, and the command returns 0.

7. Command options

usart6_hello [-d device] [-b baud] [-t seconds] [-i milliseconds]

-d  UART device; default /dev/ttyS1
-b  57600, 115200, 230400, 460800, or 921600
-t  test duration 1..600 seconds; default 30
-i  hello interval 100..10000 ms; default 1000

To debug an adapter that cannot reliably operate at 921600, test both ends at 115200:

# Minicom profile/CLI must also use 115200
nsh> usart6_hello -b 115200 -t 30

This proves the physical UART at 115200 but does not prove that the adapter/wiring is reliable at the DDS operating rate. Repeat at 921600 for final acceptance.

8. Restore Micro XRCE-DDS

  1. Exit adapter minicom with Ctrl-A, X so it releases the serial device.
  2. Reboot PX4 from CN1; generated startup will reclaim TEL1 for DDS.
  3. Start the host Micro XRCE-DDS Agent, not minicom, on the adapter.
nsh> reboot

# Host after reboot
boards/st/nucleo-h753zi/host/scripts/run_agent.sh \
  /dev/serial/by-id/<usb-uart-adapter> 921600

Verify with uxrce_dds_client status. Never leave minicom open when starting the agent.
