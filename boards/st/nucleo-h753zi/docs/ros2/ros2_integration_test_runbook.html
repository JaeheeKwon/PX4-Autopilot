Safety: remove propellers and disconnect actuators. The supplied applications never publish arming or flight setpoints. Stop at the first failed gate.

2. Test topology

One PC may perform both roles. With two PCs, use the exact same PX4 commit on both so firmware and px4_msgs match.

7. Wire USART6 and identify devices

7.1 Detailed Micro XRCE-DDS USART6 connection

LayerRequired settingCommon mistake
Electrical3.3 V TTL/CMOS, common groundUsing a true ±RS-232 adapter or connecting 5 V logic.
UART framing921600 baud, 8-N-1Adapter or terminal left at 57600.
Flow controlNone; only TX, RX, GNDEnabling RTS/CTS or connecting DTR reset.
PX4/NuttXTEL1 → /dev/ttyS1 → USART6 AF7Using CN10 D0/D1 or allowing MAVLink to claim ttyS1.
HostStable adapter by-id pathUsing a changing ttyUSB number or selecting CN1/CN13.
ProtocolMicro XRCE-DDS serial framingOpening the port in a serial terminal while the agent is running.

7.2 Power-off wiring sequence

  1. Disconnect CN1, CN13, and the USB-UART adapter from USB.
  2. Connect CN12-61/PG14 to adapter RX.
  3. Connect CN11-63/PG9 to adapter TX.
  4. Connect board GND to adapter GND.
  5. Insulate or remove the adapter VCC lead. Leave all flow-control leads open.
  6. Inspect continuity and confirm TX/RX are crossed.
  7. Connect CN1 first to power the Nucleo, then connect the adapter to the host.
  8. Identify the adapter by-id path before starting MicroXRCEAgent.

For initial bring-up, keep the three signal wires short and separated from motor/power wiring. Only one process may open the adapter serial device.

7.3 Pin table

BoardLocationAdapter
PG14 / USART6 TXCN12-61, also D2RX
PG9 / USART6 RXCN11-63TX
GNDCN12-63 or another GNDGND
PowerNot connectedLeave VCC/5 V open

No USART6 bridge modification is required. Keep SB12/SB19 ON for USART3 VCP. Do not use D0/D1.

7.4 Linux device identity and permissions

sudo dmesg --follow
ls -l /dev/serial/by-id/
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null
udevadm info --query=all --name=/dev/ttyUSB0
sudo usermod -aG dialout "$USER"

Connect one device at a time and record its by-id path. Log out/in after adding dialout. Never infer CN1/CN13 from ttyACM number.

8. ROS 2 Humble host setup

sudo apt update
sudo apt install -y locales software-properties-common curl
sudo locale-gen en_US en_US.UTF-8
sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
export LANG=en_US.UTF-8
sudo add-apt-repository universe
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  -o /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] \
http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" \
| sudo tee /etc/apt/sources.list.d/ros2.list >/dev/null
sudo apt update
sudo apt upgrade -y
sudo apt install -y ros-humble-ros-base ros-dev-tools
sudo rosdep init
rosdep update
source /opt/ros/humble/setup.bash
echo 'source /opt/ros/humble/setup.bash' >> ~/.bashrc
ros2 doctor --report

If rosdep init reports that it was already initialized, continue with rosdep update. Treat other errors as failures. Record corporate mirror/proxy substitutions. Do not mix Ubuntu or ROS releases.

13. Gate C — Serial XRCE session

Agent terminal:

cd ~/PX4-Autopilot
boards/st/nucleo-h753zi/host/scripts/run_agent.sh \
  /dev/serial/by-id/<usb-uart-adapter> 921600

Expect client/session and DDS entity creation. On NSH:

uxrce_dds_client status
# Diagnostic manual start only if no client exists:
uxrce_dds_client start -t serial -d /dev/ttyS1 -b 921600

Never start two clients on one UART. In a sourced ROS shell:

ros2 topic list | sort | grep /fmu/
ros2 topic info --verbose /fmu/out/vehicle_status_v4
ros2 topic info --verbose /fmu/in/onboard_computer_status
PASS: stable session and endpoints. STOP: on reconnect loops.

19. Cleanup and recovery

pgrep -a MicroXRCEAgent || true
ros2 node list

Stop agent/monitor with Ctrl-C. Restore 1001/1 parameters. For a non-booting board: disconnect CN13/UART, power with CN1, verify ST-LINK, reflash bootloader at 0x08000000, then known-good app at 0x08020000, reconnect one interface at a time, and repeat B–D. Restore calibrated parameters from backup.
