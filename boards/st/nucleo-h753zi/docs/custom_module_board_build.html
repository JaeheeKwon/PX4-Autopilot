Adding a Custom Module to a Specific Board Build

This page explains how to add a PX4 module so it is compiled only into a selected board target, using the ST Nucleo-H753ZI target as the concrete example.

The key idea is simple:

  1. Put the module source under src/modules/<module_name>.
  2. Give the module a CMakeLists.txt and Kconfig.
  3. Enable the generated CONFIG_MODULES_<MODULE_NAME> symbol only in the board .px4board file that should include it.
  4. Start the module manually or from a board startup script.

The markdown source for this page is custom_module_board_build.md.

Build Flow

Compiling a module into the firmware does not automatically run it. Runtime startup is a separate decision.

Module Location

For production code, use:

src/modules/my_auto_wp/

For throwaway experiments, examples are possible:

src/examples/my_auto_wp/

The config prefix changes based on the top-level folder:

Source locationBoard config symbol
src/modules/my_auto_wpCONFIG_MODULES_MY_AUTO_WP=y
src/examples/my_auto_wpCONFIG_EXAMPLES_MY_AUTO_WP=y
src/systemcmds/my_toolCONFIG_SYSTEMCMDS_MY_TOOL=y

For flight behavior, navigation logic, health monitoring, or board-specific runtime services, use src/modules. Use src/examples only for demonstrations.

Minimal Module Files

Create this directory:

src/modules/my_auto_wp/

Add CMakeLists.txt:

px4_add_module(
	MODULE modules__my_auto_wp
	MAIN my_auto_wp
	SRCS
		MyAutoWp.cpp
		MyAutoWp.hpp
	DEPENDS
		px4_work_queue
)

Add Kconfig:

menuconfig MODULES_MY_AUTO_WP
	bool "my_auto_wp"
	default n
	---help---
		Enable my_auto_wp

The important naming relationship is:

ItemValue
Directorysrc/modules/my_auto_wp
CMake module namemodules__my_auto_wp
Runtime commandmy_auto_wp
Kconfig symbolMODULES_MY_AUTO_WP
Board optionCONFIG_MODULES_MY_AUTO_WP=y

Enable It for Nucleo-H753ZI Only

Edit:

boards/st/nucleo-h753zi/default.px4board

Add:

CONFIG_MODULES_MY_AUTO_WP=y

Then build:

make st_nucleo-h753zi_default

This includes the module in the Nucleo-H753ZI firmware without enabling it for other boards.

Use a Board Variant Instead of Default

If the module should not be in the normal default image, create a separate board variant file:

boards/st/nucleo-h753zi/my_auto_wp.px4board

For non-default PX4 board labels, the build merges default.px4board with the variant .px4board, so put only the differences in the variant:

CONFIG_MODULES_MY_AUTO_WP=y

Build the variant:

make st_nucleo-h753zi_my_auto_wp

Use this pattern when you want to keep the stock default.px4board unchanged and maintain a separate experimental image.

Start the Module

After flashing, use NSH or the QGroundControl MAVLink console:

my_auto_wp start
my_auto_wp status
my_auto_wp stop

If the command is not found, the module was not compiled into the image. Check the board .px4board option and rebuild.

Start Automatically on This Board

To start the module on every Nucleo-H753ZI boot, add a startup command to:

boards/st/nucleo-h753zi/init/rc.board_defaults

Example:

my_auto_wp start

For a module that should run only when a parameter is enabled, gate the startup:

if param compare MYAUTO_EN 1
then
	my_auto_wp start
fi

Use board startup for board-specific services. Use airframe startup when the module should follow a vehicle configuration rather than the hardware target.

Board-Specific Parameters

If the module needs parameters, add parameter metadata through the module configuration path used by normal PX4 modules.

Example CMakeLists.txt with parameter metadata:

px4_add_module(
	MODULE modules__my_auto_wp
	MAIN my_auto_wp
	SRCS
		MyAutoWp.cpp
		MyAutoWp.hpp
	MODULE_CONFIG
		params.yaml
	DEPENDS
		px4_work_queue
)

Then define parameters in:

src/modules/my_auto_wp/params.yaml

Set Nucleo-H753ZI-specific defaults in:

boards/st/nucleo-h753zi/init/rc.board_defaults

Example:

param set-default MYAUTO_EN 1
param set-default MYAUTO_RATE 20

Common Mistakes

SymptomLikely causeFix
Couldn't find path for my_auto_wp during configureCONFIG_MODULES_MY_AUTO_WP=y is set, but src/modules/my_auto_wp does not existCheck directory spelling and underscores.
Build succeeds but my_auto_wp is not found in NSHModule was not enabled in the active board .px4boardConfirm the exact target being built and the config file it uses.
Module is compiled but does not runCompile-time inclusion and startup are separateRun my_auto_wp start or add it to rc.board_defaults.
The module appears on every boardOption was added to multiple board configs or a shared config pathKeep CONFIG_MODULES_MY_AUTO_WP=y only in the intended board file.
Runtime command name is different than expectedMAIN in px4_add_module does not match the command you are typingUse MAIN my_auto_wp for command my_auto_wp.

Recommended Pattern for This Board

For Nucleo-H753ZI HITL development:

  1. Add the module under src/modules/my_auto_wp.
  2. Add CONFIG_MODULES_MY_AUTO_WP=y to boards/st/nucleo-h753zi/default.px4board or to a custom variant .px4board.
  3. Build with make st_nucleo-h753zi_default or the variant target.
  4. Start manually first from NSH.
  5. Add startup to rc.board_defaults only after the manual command is stable.

This keeps build selection, runtime startup, and board defaults separate, which makes the change easier to test and easier to remove.
