Nucleo-H753ZI Board Review Findings and Action Plan

Scope: boards/st/nucleo-h753zi, no-sensor/no-SD HITL setup, internal flash parameter storage.

Executive Summary

The current flashfs-based board layout is internally consistent: the app image is capped before sector 15, the bootloader protects the reserved sector, and parameters are initialized from the last 128 KiB flash sector. The remaining improvements are mostly documentation accuracy, dependency trimming, and deciding whether a LittleFS parameter store is worth reserving more flash.

The main design warning is that stock LittleFS is not a good fit for exactly one 128 KiB STM32H7 erase sector. LittleFS allocates metadata as block pairs, so a one-sector device has no usable second erase block. A reliable LittleFS conversion should reserve the last two 128 KiB sectors.

Findings

1. HITL documentation can cause USB serial contention

Severity: Medium Area: Documentation / HITL workflow

Evidence: README.md and docs/hils_ros2_setup.md imply QGroundControl and jMAVSim can both connect directly to the same board USB serial device.

Impact: jMAVSim should own the board's /dev/ttyACM* link during classical MAVLink HITL. QGC should normally connect over UDP through jMAVSim. If both processes try to open the same serial device, one process may fail to connect or may hang during shutdown.

Action plan:

  1. Update the jMAVSim section to state that jMAVSim owns /dev/ttyACM*.
  2. Update the QGC section to say QGC connects via UDP while jMAVSim is running with -q.
  3. Add a short troubleshooting note: if jMAVSim or QGC will not close, check for a stuck serial owner with lsof /dev/ttyACM* and terminate that process.

2. LittleFS is enabled but the active parameter backend is flashfs

Severity: Medium Area: Storage configuration

Evidence: src/init.c calls parameter_flashfs_init(), while default.px4board enables CONFIG_SYSTEMCMDS_MKLITTLEFS and the NuttX defconfig enables CONFIG_FS_LITTLEFS.

Impact: If the board remains on flashfs, LittleFS adds build and dependency surface without being used. If the board moves to LittleFS, the board must mount a LittleFS volume before rcS runs param select and param load-or-init.

Action plan:

  1. If staying on flashfs, remove LittleFS and mklittlefs from this board configuration.
  2. If switching to LittleFS, add CONFIG_BOARD_ROOT_PATH="/fs/flash" and CONFIG_BOARD_PARAM_FILE="/fs/flash/params".
  3. Mount the reserved flash partition as LittleFS in board_app_initialize() before px4_platform_configure().
  4. Keep CONFIG_SYSTEMCMDS_BSONDUMP=y for parameter-store diagnostics.

3. One-sector LittleFS is not reliable with stock NuttX LittleFS

Severity: Medium Area: Storage design

Evidence: STM32H7 internal flash erase sectors are 128 KiB. NuttX LittleFS maps LittleFS blocks to MTD erase blocks. LittleFS directory metadata allocation uses a pair of blocks, so a one-block filesystem is expected to fail formatting or quickly fail writes.

Impact: Replacing flashfs with LittleFS while keeping only sector 15 reserved is likely to fail at mount/format time or be fragile under writes.

Action plan:

  1. Use flashfs if the hard requirement is exactly one 128 KiB flash sector.
  2. Use LittleFS only if the board can reserve the last two sectors, sectors 14 and 15.
  3. When reserving two sectors, reduce app flash from 1792 KiB to 1664 KiB and update the bootloader reservation from one sector to two sectors.

4. Physical GPS and RC modules are probably unused in HITL-only mode

Severity: Low Area: Firmware size / startup surface

Evidence: CONFIG_DRIVERS_GPS, CONFIG_DRIVERS_RC_INPUT, and CONFIG_MODULES_RC_UPDATE are enabled, while the board has no physical sensors and defaults to COM_RC_IN_MODE=4.

Impact: These modules consume flash and add runtime surface. HIL GPS enters through MAVLink, not the physical GPS driver.

Action plan:

  1. Keep the modules if CN10 UART GPS/RC support is planned.
  2. Otherwise remove them and rebuild to quantify flash savings.
  3. After removal, verify jMAVSim still publishes vehicle_gps_position, sensor_accel, and sensor_gyro.

5. HITL arming defaults should remain explicitly bench-only

Severity: Low Area: Safety defaults

Evidence: rc.board_defaults disables physical supply checks, ignores RC input, disables pre-takeoff auto-disarm, and disables magnetometer requirements.

Impact: These defaults are correct for a no-sensor HITL board. They would be unsafe if copied to a flight-capable target without review.

Action plan:

  1. Keep the defaults for this board as long as it remains HITL-only.
  2. Add a short warning to the README that the target is not a flight configuration.
  3. If a real-sensor variant is added later, create a separate board target or airframe path instead of weakening these defaults conditionally.

6. README parameter table is incomplete

Severity: Low Area: Documentation maintenance

Evidence: The README lists only a subset of the defaults in init/rc.board_defaults.

Impact: Future debugging can drift because the README does not show the full HITL defaults that actually determine arming and estimator behavior.

Action plan:

  1. Either replace the README table with a link to docs/hitl_configuration.md, or expand the table to match rc.board_defaults.
  2. Treat rc.board_defaults as the source of truth.

Recommended Sequence

Order Work item Validation
1 Clarify jMAVSim/QGC serial ownership in docs. Follow the doc from a clean terminal session and confirm QGC connects over UDP while jMAVSim owns serial.
2 Choose final parameter backend: flashfs one-sector, or LittleFS two-sector. Confirm app image still fits after any flash reservation change.
3 If moving to LittleFS, apply the isolated patch in boards/st/nucleo-h753zi/littlefs. Build, flash, boot, then run ls /fs/flash, param save, reboot, and confirm parameter persistence.
4 Optionally trim unused GPS/RC modules. Verify HITL sensor topics and arming workflow are unchanged.

Status

Current flashfs implementation: consistent and buildable.

LittleFS implementation package: provided separately under boards/st/nucleo-h753zi/littlefs, with the recommendation to reserve two sectors.
